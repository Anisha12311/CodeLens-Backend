# CodeLens backend

The Express API behind [CodeLens](../frontend/README.md). It turns a coding problem into a
step-by-step walkthrough, saves it in Supabase, and serves the shared library.

## How it works

1. `POST /api/generate` receives a problem and an optional example.
2. The problem's name is normalised (`"1. Two Sum."` and `"two sum!"` both become `two sum`). If a
   walkthrough for that name is already saved, it is returned straight away.
3. Otherwise the walkthrough is generated with Groq, falling back to OpenRouter if Groq fails.
4. The result is saved to the `walkThroughs` table and returned.

## Run it

```bash
npm install
npm run dev        # http://localhost:5000
```

For production:

```bash
npm run build      # compiles to dist/
npm start
```

## Environment

Create a `.env` file in this folder. Never commit it.

```bash
PORT=5000
SUPABASE_URL=https://<project>.supabase.co
SUPABASE_SECRET_KEY=<service role key>
GROQ_API_KEY=<groq key>
GROQ_MODEL=openai/gpt-oss-120b
OPENROUTER_KEY=<openrouter key>
OPENROUTER_MODEL=<openrouter model id>
```

## Database

Run this in the Supabase SQL editor:

```sql
create table if not exists public."walkThroughs" (
  id           bigint generated by default as identity primary key,
  cache_key    text unique not null,
  problem      text not null,
  example      text,
  walkthrough  jsonb,
  creator_hash text,
  created_at   timestamptz not null default now()
);
```

## API

| Method   | Path                    | What it does                                                    |
| -------- | ----------------------- | --------------------------------------------------------------- |
| `POST`   | `/api/generate`         | Body `{ "problem": "...", "example": "..." }`. Returns a walkthrough, saved or new. |
| `GET`    | `/api/walkthroughs`     | The 50 newest saved problems: `id`, `title`, `problem`, `example`, `canDelete`. |
| `GET`    | `/api/walkthroughs/:id` | One saved walkthrough's full JSON.                              |
| `DELETE` | `/api/walkthroughs/:id` | Deletes a problem. Only its creator can; others get `403`.      |

### Limits

- The problem can be up to 6000 characters, and the example up to 400.
- Each IP can make 5 new walkthroughs per minute. Saved problems don't count.
- A generation request times out after 90 seconds.

### Errors

Errors return `{ "code": "...", "message": "..." }`. The codes are `bad_request`, `too_large`,
`too_many_requests`, `rate_limited`, `timeout`, `upstream`, `invalid_json`, `forbidden`,
`not_found` and `database`.

### Who can delete

The frontend gives each browser a random ID and sends it in the `X-Creator-Id` header. The backend
stores only a SHA-256 hash of it in `creator_hash`, and deletes a row only when the hash matches.
The hash is never sent back; the list returns a `canDelete` flag instead.

## Test it

```bash
curl -X POST http://localhost:5000/api/generate \
  -H "Content-Type: application/json" \
  -d '{"problem": "Two Sum", "example": "nums = [2,7,11,15], target = 9"}'

curl http://localhost:5000/api/walkthroughs
```

## Layout

```
server.ts                 Starts Express and mounts /api
routes/                   generate, walkthroughs, users
controller/               Request handlers
middleware/               Input checks, saved-problem lookup, rate limit
services/                 Groq and OpenRouter calls
utils/                    Problem name key, creator hash
config/supabase.ts        Supabase client
types/                    Shared types
```
